**S2 · 01 PLAN.** When: before anything touching 2+ files.
`Before you change anything: read the relevant files, then give me a numbered plan. For each step: file, change, why. Don't edit until I say "go".`

**S3 · 02 ASK.** When: the task is fuzzy.
`Before planning, ask me up to 5 questions, only ones whose answers would change what you build.`

**S4 · 03 SMALL.** When: the plan looks too big.
`What's the smallest change that meets the acceptance criteria? If it touches more than 3 files, justify each.`

**S5 · 04 PROVE.** When: it says "done".
`Run [test command] and paste the actual output. If anything fails, fix it and run again.`

**S6 · 05 REVIEW.** When: before you commit.
`Review your own diff as a strict senior engineer. List bugs, things I didn't ask for, and things you're unsure about. Fix the first two.`

**S7 · 06 EXPLAIN.** When: new codebase, or code you forgot.
`Explain how [module] works as if I'm a new teammate: entry points, data flow, and the 3 files to read first.`

**S8 · 07 UNSTICK.** When: it's going in circles.
`Stop. Summarise what you tried and why it failed. Propose 2 different approaches and recommend one. No code yet.`

**S9 · 08 HANDOFF.** When: the session is getting long.
`Summarise this session for a fresh one: done, left, decisions, gotchas. Under 15 lines.`
