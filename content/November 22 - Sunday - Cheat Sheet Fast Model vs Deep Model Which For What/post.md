**S2 · Use the DEEP model for…**
- Planning a feature across many files
- Debugging something you don't understand
- Architecture and design trade-offs
- Vague or ambiguous asks

**S3 · Use the FAST model for…**
- Executing a clear, approved plan
- Renames, small refactors, formatting
- Writing tests from explicit criteria
- Summaries, release notes, commit messages

**S4 · The combo that works**
- Headline: "Plan with deep → execute with fast → review with deep."
- Visual: 3-step strip with a brain icon on each

**S5 · Signs you picked wrong**
- Fast model: "loops, misses context, confidently wrong on the hard part" → go deep
- Deep model: "a 3-minute wait to rename a variable" → go fast

## Caption
Stop using your most expensive AI model for everything.

🧠 DEEP model: planning across files, debugging the unknown, architecture, vague asks
⚡ FAST model: executing an approved plan, renames, tests from clear criteria, summaries

The combo: plan with deep → execute with fast → review with deep.

Wrong pick? A fast model looping on a hard problem → go deep. A 3-minute wait to rename a variable → go fast.
