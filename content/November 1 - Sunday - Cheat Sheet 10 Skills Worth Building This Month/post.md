**S2 · Ship it** (3 cards)
1. **release-notes**: git log → customer-friendly notes
2. **pr-description**: diff → a PR description with a test plan
3. **changelog-check**: flags user-facing changes missing from the changelog

**S3 · Keep it healthy** (3 cards)
4. **dep-audit**: lists outdated or unused dependencies, with the risk of each
5. **flaky-test-hunt**: re-runs the suite and reports tests that flip
6. **dead-code-scan**: finds exports nothing imports

**S4 · Understand it** (2 cards)
7. **explain-module**: "new teammate" tour of any folder
8. **decision-log**: appends a decision to CLAUDE.md in the house format

**S5 · Talk about it** (2 cards)
9. **weekly-update**: commits + closed issues → a 5-line stakeholder update
10. **bug-triage**: an issue → repro steps, suspected files, severity

**S6 · Make any of them work**
- "Description = when to use it" · "Numbered steps with real commands" · "One 'never' line"

**S7 · The one I'd start with**
- Headline: "weekly-update, if you have a boss. release-notes, if you have users."
